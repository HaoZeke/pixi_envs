* About

This directory provides [[https://pixi.sh][pixi]] development environments for the *rgpkgs*
suite — Python packages for computational chemistry — kept *out-of-tree* from
the git remotes so env matrices do not pollute source repos.

* Ecosystem architecture

** Packages

| Package | Role | Repository |
|---------+------+------------|
| *rgpycrumbs* | *Hub*: basetypes, surfaces/geom, ~ensure_import~, lock/config, *CLI dispatcher* | [[https://github.com/HaoZeke/rgpycrumbs][HaoZeke/rgpycrumbs]] |
| *chemparseplot* | *Library*: parsers + plot primitives (NEB/min/saddle, strips, themes) | [[https://github.com/HaoZeke/chemparseplot][HaoZeke/chemparseplot]] |
| *pychum* | *Library*: input generators (ORCA, eOn templates) | [[https://github.com/HaoZeke/pychum][HaoZeke/pychum]] |

External peers: *readcon* (CON I/O, ≥0.14.7 for current eOn CON spec 3), *ira* / ~ira_mod~ (conda),
*eb-stack* (EasyBuild lock + CycloneDX produce; not a Python package here).

** Design principles

1. *rgpycrumbs is the hub* for CLI, ~ensure_import~, lock consume, suite TOML.
2. *chemparseplot* stays a library (no second CLI hub, no ~./config/chemparseplot~).
3. *One pin/lock policy* for the whole suite (~rgpkgs.toml~, ~RGPKGS_*~).
4. *Hub has no runtime feature extras*; heavies resolve via PEP 723 + uv or AUTO_DEPS.
5. *chemparseplot extras* (~plot~, ~neb~, …) are *transitional install convenience* —
   target is the *same uv / ensure_import design* as the hub (drop host extras over
   time; scripts/tools pull deps on demand). Prefer bare ~pip install chemparseplot~
   + suite pins / uv for new work.
6. *Host envs stay lean* (cookbook): bare hub + job hosts (eon, readcon, torch…),
   not jax/adjustText/chemparseplot “because plots”.
7. *Formal stack SBOM* is produced by eb-stack (or ~uv export~); hub *consumes*
   locks/SBOM, does not invent EasyBuild inventory.

** Library API vs CLI (cookbook and notebooks)

*Target:* notebooks prefer the *library API* —
~chemparseplot.plot.neb~ / ~chemparseplot.parse…~ and ~rgpycrumbs~ basetypes/surfaces —
so figures and data stay in-process.

*Today:* the full eOn plot *pipeline* (history aggregation, landscape GP, structure
strips, CLI flags) still lives primarily behind ~rgpycrumbs eon plt-*~ PEP 723
scripts. Cookbook therefore dispatches the CLI with ~RGPKGS_FORCE_UV=1~ (or
~RGPYCRUMBS_FORCE_UV~) until those pipelines are exposed as stable library
entrypoints. That is a *product gap*, not the preferred long-term shape.

When promoting a plot path to library-first:

1. Stable function on chemparseplot (or thin rgpycrumbs wrapper).
2. CLI becomes a thin flag→kwargs layer over that function.
3. Cookbook switches to the function call; keep FORCE_UV only if still subprocessing.

** Dependency resolution matrix

| Context | Mechanism |
|---------+-----------|
| ~rgpycrumbs eon plt-*~ | Dispatch: uv + PEP 723 ± suite lock constraints; or in-env + ensure_import |
| ~import chemparseplot…~ | Host has deps *or* soft import; heavies ideally via hub ensure_import later |
| ~import rgpycrumbs.surfaces~ | ~ensure_import("jax")~ + AUTO_DEPS / suite pins |
| Cookbook CI | Lean env + FORCE_UV + bare ~rgpycrumbs~ + ~readcon~ |
| Site-wide pins | ~/~/.config/rgpkgs/config.toml~ → ~pins.lock~ / ~pins.packages~ |
| HPC EasyBuild | eb-stack CycloneDX/lock → ~RGPKGS_LOCK~ (non-PyPI rows skipped) |

** Suite config (one tree for all packages)

| Layer | Path |
|-------+------|
| User | ~/~/.config/rgpkgs/config.toml~ |
| Project | ~rgpkgs.toml~ / ~.rgpkgs.toml~ (walk up from CWD) |
| Env | ~RGPKGS_CONFIG~, ~RGPKGS_LOCK~, ~RGPKGS_FORCE_UV~, ~RGPKGS_AUTO_DEPS~ |
| Legacy | ~rgpycrumbs.toml~, ~/~/.config/rgpycrumbs/~, ~RGPYCRUMBS_*~ still load |

Precedence: *CLI → env → project TOML → user TOML → defaults*.

Shared schema (excerpt; full example in
~rgpycrumbs/docs/examples/rgpkgs.config.toml~):

#+BEGIN_SRC toml
[pins]
lock = "uv.lock"              # or pylock.toml / CycloneDX JSON

[pins.packages]
jax = "0.4.31"

[rgpycrumbs.dispatch]
auto_deps = true
force_uv = false

# later: [chemparseplot.plot] …
#+END_SRC

chemparseplot and pychum *must not* invent parallel XDG trees; they import
~rgpycrumbs.config~ / ~rgpycrumbs.locks~ when they need pins.

** Version floors (suite table)

| Consumer | Floor |
|----------+-------|
| rgpycrumbs eOn CLI (PEP 723) | ~chemparseplot[neb,plot]>=1.9.17,<2~, ~readcon>=0.14.7~, ~rgpycrumbs>=1.10.4~ in script headers |
| chemparseplot ~neb~ extra (while it remains) | ~readcon>=0.14.7~ |
| pychum | ~rgpycrumbs>=1.10.4~ |
| Cookbook hub pin | ~rgpycrumbs>=1.10.4~ (bare, no extras) |

Release train: ship chemparseplot plot API changes first; bump rgpycrumbs PEP 723
floors in the same window; bump pychum only when it needs new hub APIs.

** Install matrix (current)

#+BEGIN_SRC bash
pip install rgpycrumbs                 # hub only — no runtime feature extras
pip install chemparseplot              # prefer bare; use suite pins / uv for plot stacks
# transitional, while extras remain:
pip install "chemparseplot[plot,neb]"  # library convenience only — not a pin system
pip install pychum                     # needs rgpycrumbs>=1.10.4

# Preferred one-shot NEB visualization (isolated uv env via dispatcher):
rgpycrumbs eon plt-neb --help
export RGPKGS_FORCE_UV=1
export RGPKGS_LOCK=./uv.lock           # optional
#+END_SRC

Do *not* ~pip install "rgpycrumbs[analysis]"~ — that extra was removed (1.9.12+).

* Quick start (this directory)

** Prerequisites

- [[https://pixi.sh][pixi]] for conda-only stacks
- [[https://docs.astral.sh/uv/][uv]] for PyPI-first development (required for CLI dispatch)

** Setup

#+BEGIN_SRC bash
cd /path/to/pixi_envs/python/rgpkgs/
git clone https://github.com/HaoZeke/rgpycrumbs.git
git clone https://github.com/HaoZeke/chemparseplot.git
git clone https://github.com/HaoZeke/pychum.git

cd rgpycrumbs
uv sync --extra test
uv run pytest -m pure
#+END_SRC

* Package-specific workflows

** rgpycrumbs

| Environment | Purpose | Key deps |
|-------------+---------+----------|
| test | Pure tests | pytest |
| surfaces | JAX surfaces | jax (pixi) |
| fragments | Fragment analysis | tblite, ira (conda) |
| eonmlflow | eOn + MLflow | eon, mlflow |
| docs | Sphinx | sphinx, emacs |

#+BEGIN_SRC bash
cd rgpycrumbs
uv run pytest -m pure
pixi run -e docs docbld
rgpycrumbs --verbose eon plt-neb --help
#+END_SRC

** chemparseplot

Library-first. Prefer bare install + suite config for pins. Extras remain only as
transitional convenience until plot deps fully follow the hub uv design.

#+BEGIN_SRC bash
cd chemparseplot
uv sync
uv run pytest
# transitional:
uv sync --extra plot --extra neb
#+END_SRC

** pychum

#+BEGIN_SRC bash
cd pychum
uv sync
uv run python -c "import pychum"
#+END_SRC

* Cookbook / host env contract

#+BEGIN_SRC yaml
# examples/*/environment.yml pattern
dependencies:
  - uv
  - pip:
    - readcon>=0.13.1      # notebook CON only
    - rgpycrumbs>=1.9.16   # bare hub
    # not: chemparseplot, jax, adjustText as plot host pins
#+END_SRC

#+BEGIN_SRC python
import os
os.environ.setdefault("RGPKGS_FORCE_UV", "1")
# optional: os.environ.setdefault("RGPKGS_LOCK", "uv.lock")
#+END_SRC
